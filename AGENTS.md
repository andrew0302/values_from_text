# AGENTS.md

This file defines the rules and context for any AI agent working in this repository.

## What this repo is
A PhD dissertation project analysing values extracted from song lyrics and political
speeches. Analysis is in R; documents are written in LaTeX (on Overleaf, not here). This
repository will eventually be submitted alongside the thesis chapter, so it must stay
clean, reproducible, and easy for a reviewer to navigate.

## Folder structure
- `_briefs/` — project briefs that agents execute, and their reports.
- `_data/` — input and intermediary data. Do not delete or modify anything here.
- `_notebooks/` — R notebooks (.qmd and .Rmd). This is the primary working area.
- `_tex/` — a read-only local copy of the Overleaf manuscript, for reference only.
  Do not edit; changes here do not sync to Overleaf and will be lost.
- `_manuscript/` — scheduled for archiving, do not touch.
- `images/` — plots generated by notebooks. Can be overwritten by re-rendering.
- `tables/` — LaTeX tables generated by notebooks. Can be overwritten by re-rendering.
- `archive/` — old material. Do not touch.
- `docs/` — site render for GitHub Pages.

Notebooks write their outputs to `images/` and `tables/` at the repo root via `here(...)`,
which is anchored to the project root — **not** to the notebook's own folder. Moving or
renaming a notebook therefore does not change where it reads or writes. This is what makes
reorganising `_notebooks/` safe.

## Key files
- `README.md` — the **living output manifest**: every manuscript figure/table → its output
  file → the notebook that produces it → its manuscript section, with a status flag. This is
  the source of truth for what feeds the manuscript. Keep it in sync: when you add, remove,
  rename, or repoint an output, update the corresponding manifest row.
- `AUDIT.md` — working notes for the current clean-up (orphans, merges, name drifts, the
  model bug). Disposable scratch, not a durable record.

## What agents may do
- Edit existing notebooks in `_notebooks/` when explicitly instructed.
- Create new code chunks, or new notebooks, when explicitly instructed.
- Rename or reorganise files within `_notebooks/` when explicitly instructed.
- Render notebooks using `quarto render <file>` or `rmarkdown::render("<file>")`
  as appropriate for the file type (.qmd or .Rmd respectively).
- Create local git commits and tags as checkpoints when a brief instructs. (Never push —
  see below.)
- Update the `README.md` manifest to reflect output changes you have made.

## What agents must not do
- **Install, update, remove, or change the version of any R package.** The R version and
  package versions are part of the analysis; changing them can silently change results. A
  missing or broken package is an **error to log and report**, not to fix.
- Clear or delete cached artifacts (`.RDS` files, Quarto `freeze`, bootstrapped ICCs)
  without explicit instruction.
- Delete any file. Move it to `archive/` instead.
- Modify anything in `_data/`, `_manuscript/`, `_tex/`, or `archive/`.
- Make analytical decisions (e.g. model specification, what to cut) without explicit
  instruction.
- Push to git without explicit instruction.

## Working from briefs
Agents execute briefs from `_briefs/`. A brief may grant **standing authorisation** for a
specific, listed set of actions — this overrides the "state plan, wait for confirmation"
default below, but only for the actions the brief explicitly lists. Anything outside a
brief's stated scope falls back to the default. Every brief defines **tripwires**; stop
immediately and leave a note if any tripwire condition is met, even mid-run.

## Git
- Agents may create local commits and tags as checkpoints when a brief instructs — these are
  cheap and revertible.
- Agents must never push. Pushing is done by the repo owner. (The owner's correct account is
  `andrew0302`; a second account causes credential conflicts, which is why pushing is left
  to the owner.)
- Prefer doing risky work (reorganisation, bulk edits) on a branch, so it can be reviewed as
  a diff before it reaches `main`.
